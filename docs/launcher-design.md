# 启动器：空状态、命令面板、多轮连接

状态：Mac 端已实现；§5 与 §9 于 2026-07-31 依实际使用改写（动词前置、页面变小、Dock 那条改准）。iOS（§10）仍未做。
取代：`prd-mac-client.md` §3.1、§五 与 `onboarding-design.md` §4.2 —— 那三节描述的是菜单栏时代"从哪进入会话"的答案，本文是新的答案。

---

## 1. 它解决什么

收缩之后，产品是"给本来就用 shell 的人的 tmux GUI 客户端"。模型就是 tmux 自己的模型，并且刻意暴露：

```
服务器（本地 / ssh 主机） → 会话 → 窗口 → pane
```

但"我要打开点什么"这个动作在两端都没有一个好地方：

- **Mac**：关掉最后一个窗口后一个窗口都没有，只剩 Dock 图标；启动时若无可恢复的会话，会凭空建一个你没起过名字的 `bento`。
- **iOS**：顶层名词是**主机**，必须 `主机列表 → 该主机的会话列表 → 终端` 三屏，并且进入中间那屏会**单独开一条 SSH 只为跑一次 `tmux ls`**。

两边都缺同一个东西，而且缺的是同一个东西。

## 2. 核心主张

**空状态不是一个新页面，它是没有蒙层的命令面板。**

把它当成新页面，就会不由自主往里塞 hero 图、标语、三步引导——那是刚删掉的 onboarding 又长回来。

一个 provider（`OpenTargets.swift`），三种渲染：

| 场景 | 形态 | 根内容 |
|---|---|---|
| 会话之上按 ⌘P | 浮层 | 全部，几百条命令 |
| 窗口存在但还没有会话 | **页面本身** | 三个"新建"动词 + "可以打开的东西"，约一屏 |
| 右键 Dock 图标 | `NSMenu`，一眼扫，无搜索 | 同上，带条数上限 |

两个根的内容量差异不是随意划的：**空窗口里没有东西可以施加命令**——分屏、查找、布局在那儿全无意义。有上下文才有命令。

⌘P 在空状态下按仍然有用：聚焦搜索框。肌肉记忆不落空。

## 3. 步骤栈

采用 VS Code quick pick 的链式模型：面板不关闭，列表整体替换，占位符显示上下文面包屑，**Esc 退一层而不是退出**。

```
level 0   空状态（页面）/ ⌘P（浮层）
            会话      bento          2 windows · 5 分钟前
            最近      claude         ~/code/bento-term
            主机      dev  [ssh] [tmux ▸]

level 1   dev › 选择会话…                    ← 每次都是实时枚举
            ↻ 正在连接 dev…        Esc 取消
            ─────────────────────────────
            build              2 windows
            scratch            1 window
            ＋ 新建会话…
            ＋ 新建 agent 会话…
            ▸ 不用 tmux，直接开 shell

level 2   dev › 会话名…                      ← 只问名字，回车即走
```

**空状态就是这个栈的第 0 层，只是不带蒙层。**所以不需要两套机制——在空状态里点主机是原地往下推，不弹新东西。

## 4. 为什么多轮交互要由面板承载

这不只是形式偏好，它解决一个结构性缺陷。

今天的流程是：点一下 → **立刻创建窗口** → 然后那个窗口得负责表达失败。这正是 2026-07-31 那个"点开远端 tmux 就卡死"的成因：一个已经存在的终端窗口，没有任何合适的方式说"其实我什么都没连上"，于是它就那么坐着。（三个并发原因见 commit `3480946`；另外 macOS 上 `showError` **从来没有被绑定过**，错误一直抛进虚空。）

改成面板承载之后：**主机解析、会话枚举、失败反馈全部发生在创建窗口之前；窗口只在你选中一个真实会话之后才诞生。**

失败于是有了天然的显示位置和天然的退出方式（Esc），而不需要给终端窗口发明一套错误 UI：

```
level 1   dev › 选择会话…
            ⚠ dev 上没有 tmux
              /bin/sh: 1: tmux: not found
            ▸ 不用 tmux，直接开 shell
```

## 5. 布局与权重

**2026-07-31 修订：动词在前，列表在后。**初版把三个列表放在页顶、把"新建"塞进页脚，实际用下来是反的——最常见的意图不是"回到某个已存在的东西"，而是"给我一个能跑一条命令的 shell"，而那恰好是当时离视线最远、要往下翻三个分区才够得着的一行。频率高的意图必须最省手。

```
┌──────────────────────────────────────────────┐
│  ⌕  输入以筛选…                    ← 默认聚焦 │
├──────────────────────────────────────────────┤
│  ▸ New Terminal without tmux                 │  ← 默认选中，⌘N ⏎ 就是它
│      A quick local shell. Closing it…        │
│    New Agent Session…                        │
│      A fresh tmux session running Claude…    │
│    New Empty Session                         │
│      A blank tmux session on the host…       │
│  ────────────────────────────────────────    │
│  Sessions                                     │
│    bento             2 windows · 5m ago      │
│    session-2         1 window  · 1d ago      │
│                                              │
│  Recent Launches                              │
│    claude       ~/code/bento-term            │
│    npm run dev  ~/code/personal-assistant    │
│    shell        ~/code/bento-acp             │
│      2 more ⌄                                │
│                                              │
│  SSH Hosts                               10 ▸ │
│    [dev] [orb] [home] [dg] …                 │
├──────────────────────────────────────────────┤
│                        ↑↓ to move · ⏎ to open │
└──────────────────────────────────────────────┘
```

顺序就是这个，四个渲染面（`+` 菜单 / Shell 菜单 / 启动器 / Dock 菜单）必须一致：

1. **New Terminal without tmux** —— 一次性 shell，单独一组、排第一、默认选中。
2. **New Agent Session… / New Empty Session** —— 两条 tmux 创建路径，成对出现。
3. **Sessions** —— 正在跑的。
4. **Recent Launches** —— 先给三条，"N more" 展开。
5. **SSH Hosts** —— chip 行 + 计数。

**列表内部的权重不变，仍然不平均分配。**

- **会话 / 最近 = "继续"**：高意图、数量少，你多半就是想回到其中一个 → 整行。
- **主机 = "去个新地方"**：`~/.ssh/config` 里可能有几十条，单条意图密度很低 → 压成一行 chip + "10 ▸"。
- **最近现在也折叠**：它掉到了动作和会话下面，六行历史会把主机挤出 520pt 的页面，而第四新的那条本来就很少被点 → 先给三条。

### 词汇：一个概念一个名字

三处旧叫法互相打架：工具栏 `+` 叫 `New Session with Agent…`，启动器页脚叫 `New Agent Session…`；Shell 菜单把空 tmux 会话叫 `New Session`，工具栏叫 `New Empty Session`；同一个无 tmux 终端在 Shell 菜单里叫 `New Window (no tmux)`。定稿：

| 概念 | 名字 | 为什么是它 |
|---|---|---|
| 一次性本地 shell | **New Terminal without tmux** | 唯一同时说清"是什么"和"缺什么"的写法；`New Window (no tmux)` 说的是窗口，可它其实是个关掉就没的终端 |
| agent 会话 | **New Agent Session…** | 与下一行构成同构（`New _ Session`），两行只差一个词；`New Session with Agent…` 破坏了这个对仗。省略号保留——它开的是向导 |
| 空 tmux 会话 | **New Empty Session** | 旁边一旦坐着 agent 会话，光说 `New Session` 就不再唯一 |

字面与解释句都收在 `LaunchAction`（`OpenTargets.swift`）里，四个面渲染同一份数据——这正是 provider 存在的前提：面之间不许各说各的。

### 筛选对动作行做什么

**动作行钉住，不参与筛选**：始终三条、始终在最上面。理由是它们不是"要找的东西"而是"这一页的动词"——只有三条、位置固定，靠的是肌肉记忆而不是搜索。

但**⏎ 必须跟着搜索结果走**：输入 `bento` 之后回车必须 attach `bento`，不能因为选中项还停在第一条动作上就变成"新建一个 shell"——把搜索变成创建是这一页唯一不能犯的错。所以有查询时默认选中第一条**匹配到的内容行**；只有当查询什么都没匹配上时才回落到动作——回落时优先按名字匹配（输入 `agent` 就落在 New Agent Session… 上），否则落回第一条。

**打开即可打字筛选**，不用先点搜索框。键盘优先。

**没东西可开时**（没会话、没历史、没有 ssh config）：页面不再是另一块空屏。三条动作本来就无条件存在，所以只把三个空标题换成一句话——"Nothing running to open — no tmux sessions, no recent launches, no hosts in ~/.ssh/config"——把找过哪三处说出来，读起来才是"确实没有"而不是"没加载出来"。搜索框的 placeholder 同时变成 `Nothing running to filter`：一个只有三条动作的页面还写着"输入以筛选"是在骗人。

### 窗口尺寸：660 × 520，并且填充时会变大

初版让启动器**继承会话窗口的 frame**，这样"选中 → 填充"是纯内容替换、不动几何。代价在实际使用中更大：⌘N 从一个近乎全屏的终端上按出来，得到的是 2544pt 宽、只装着一个搜索框和九行的空页。

现在：启动器固定 **660 × 520 居中**。660 是命令面板的宽度——同一份列表在浮层里读和在页面上读应该是同一个尺度；520 高刚好装下三条动作 + 三四个会话 + 三条最近 + chip 行，常见情况不滚动。

代价照单全收：**填充时窗口会明显变大**。`TerminalWindowManager.init(adopting:)` 原先对 adopted 窗口跳过 `setFrameUsingName` / `setContentSize`，现在不跳了，会把会话窗口那份记住的几何应用上去（没有记住的就是 980×640）。否则结局是"会话装在一个启动器大小的窗口里"——同一笔交易的另一头，更糟。

**不加动画**：这次改尺寸和 ghostty surface 的创建落在同一个 runloop turn 里，没有一个稳定的"之前"可供动画；真加了动画就是让 ghostty 的字符网格走过十几个中间尺寸，每一个都是一次 tmux resize，而那个 session 还没 attach 完。

### 不放这些
hero 图、标语、架构图、"三步开始使用"。空状态的职责只有一句：**这些是你可以打开或新建的东西。**

## 6. 主机行的两个动作

```
dev                                      [ssh]  [tmux ▸]
```

- **`ssh`** —— 立刻开一个普通 ssh 窗口。**零网络等待**，不枚举。
- **`tmux ▸`** —— 推进 level 1（实时枚举）。

## 7. 新建会话的两条路径，形态不同

对应现有的两种创建方式，且**刻意不做成同一种形态**：

- **普通会话** —— 留在面板里，一个输入框，回车即走。它就该只有一道题。
- **agent 会话** —— 从面板**跳出**到现有的向导表单，不链式化。

理由：布局选择是**二维的**（`TmuxLayout` 的九宫格 / 主从 / 三列，带 SF 图标），线性 quick pick 渲染不了；硬拆成四步问答（名字→目录→agent→布局）比一张表单更烦。VS Code 同样如此——有些命令开的是编辑器而不是继续链式。

**面板负责路由，不负责承载一切。**

## 8. 不缓存枚举结果

已决定：`tmux ▸` 每次都实时枚举。三个后果：

1. **异步层的取消与进度不是可选项。** 每次都是真实往返（`dev` 实测约 300ms，链路差时数秒）。必须有进行中指示，**Esc 必须真的杀掉那条 ssh**。
2. **不许预取。** 不能因为"反正要连"就在悬停时预热——那会在你只是划过列表时对每台主机发起 ssh。只在显式动作时连接。
3. **iOS 根屏的"会话"分区被掏空** —— 见 §10 待决。

## 9. Mac 的空状态何时出现

三条，按 `openMainWindow` 的实际分支写（本节此前把 Dock 那条说宽了）：

- **启动时**：`mac_last_terminal_sessions` 为空（或里面的会话在服务器上都不在了）→ 启动器。有可恢复的就直接恢复，不问。
- **Dock 图标唤起时**：`ccbeb3a` 之后**不只是**"无可恢复的会话"这一种情况。本次运行内如果用户**自己把窗口一个个关光了**，`closedEverythingByHand` 会置位，之后点 Dock 图标一律出启动器，即便恢复列表非空——手动清空屏幕是一个决定（"我收拾完了，给我看看有什么"），和 ⌘Q 之后回来（"我做到一半"）不是同一件事。该标记在任何会话窗口重新存在时立刻清掉，⌘Q 走 `isTerminating` 不置位，所以下次冷启动照样恢复。
- **⌘N**（见下）

**关掉最后一个窗口仍然是没有窗口**（既有决定不变）。空状态是"窗口存在但还没内容"，不是"没有窗口"。

### ⌘N 的语义修正

现状（commit `4f93e6b`）是"⌘N 立刻新建窗口 + 一个自动命名的新会话"。有了空状态之后改为：

- **⌘N** = 开一个新窗口，**然后问你要放什么**（空状态）
- **⌘⇧T** = 别问，直接给我一个 **New Empty Session**
- **⌥⇧⌘T** = 别问，直接给我一个 **New Terminal without tmux**

三种意图本来就存在，给它们各一个键，都诚实。现状的问题是 ⌘N 会创建一个叫 `session-3` 的东西——一个你没起过的名字。

而且 §5 改序之后，⌘N 也不再只是"问你"：默认选中就是 New Terminal without tmux，所以 **⌘N ⏎ = 一次性 shell**，比 ⌥⇧⌘T 更好按，也正好是最高频的那个意图。

## 10. iOS / iPadOS 对齐

**同样四个分区、同样顺序、同样词汇。区别只在生命周期**：Mac 上它是**空状态**（偶尔出现），iOS 上它就是**根**（永远是第一屏）。

这同时替掉了 iOS 的"每台主机一屏会话列表"这个中间层，那两次 SSH（其中一次只为跑 `tmux ls`）也收敛成面板里的一次枚举。

iPhone 上面板是 sheet / push，iPad 上是同一个面板；iPad 的根应改为 `NavigationSplitView`（侧边栏 = 这份列表，detail = 终端），对应 Mac 的"会话 = 窗口标签，tmux 窗口 = 侧边栏"。

**⚠ 待决**：§8 的不缓存决定会让 iOS 根屏的"会话"分区只剩当前已连接的那些，其余会话必须先选主机再等一次往返才可见——**iOS 的顶层名词会因此被迫退回"主机"**，也就是本文一开始要解决的问题。Mac 没这个问题，因为本地 `tmux ls` 是瞬时的。

倾向：**iOS 破例缓存**。失效风险很低——显示一个已被别处杀掉的会话，点下去是 `new-session -A`，会重建同名的，不报错。

## 11. 词汇

统一到 Mac 的 `服务器 / 会话 / 窗口 / pane`，连接动作只用一个动词。

iOS 现状有五个动词（Connect / Attach / Start / Create / Open / Launch），一屏之内就能看全；且 `Host` 与 `Server` 的用法与 Mac 相反（iOS 管机器叫 Host，却把 hostname/port 那节叫 Server）。

另有一处假话待清：`WelcomeFlowView` 写着 "Reads your ~/.ssh/config" —— iOS 上没有任何 ssh config 读取，那是 Mac 刚获得的能力。

**未决**：`Focus / Parallel` 是 iOS 独有的、盖在 tmux 窗口之上的一层说法，Mac 的模型里没有这个名词。要么 Mac 采纳，要么 iOS 放弃，不能两端各说各的。这是产品身份问题。

## 12. 不在本设计范围内的后续工作

- **交互式认证 UI**。需要密码 / 2FA / 未验证 host key 的主机**目前完全不可用**：界面渲染的是 tmux 面板，而 tmux 根本没启动，没有地方输入。现在会在 12 秒后失败并引用真实提示文本，不再永久卡死。但"任何 sshd + tmux"这个前提要求它必须被解决。
- **远端 agent 会话**。目录选择现在用 `NSOpenPanel`（本地文件系统），远端需要走 ssh 的目录浏览器；agent 探测现在是本地 `command -v` 且只返回第一个装了的，远端需要一次往返探测全部。这块与"最近"分区里的远端目录是同一批基础设施。
- **App Intents / Spotlight**。同一个 provider 的第四个出口。
