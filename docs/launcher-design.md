# 启动器：空状态、命令面板、多轮连接

状态：Mac 端已实现；§2 / §5 / §6 于 2026-07-31 第三次改写——**启动器页面不再是"命令面板的第 0 层"，它就是一张页面**：居中的两栏内容块，左栏品牌＋动词，右栏正在跑的与最近的；页面自己不搜索，工具栏搜索框在这里和在会话窗口里是同一个东西（⌘P 命令面板）。此前两次改写分别是：依实际使用把动词前置、把 Dock 那条改准；以及把"启动器是另一种窗口"这个错误前提整段拆掉（同一个窗口、同一个工具栏、同一份几何记忆，只是还空着）。iOS（§10）仍未做。
取代：`prd-mac-client.md` §3.1、§五 与 `onboarding-design.md` §4.2 —— 那三节描述的是菜单栏时代"从哪进入会话"的答案，本文是新的答案。

---

## 1. 它解决什么

收缩之后，产品是"给本来就用 shell 的人的 tmux GUI 客户端"。模型就是 tmux 自己的模型，并且刻意暴露：

```
服务器（本地 / ssh 主机） → 会话 → 窗口 → pane
```

但"我要打开点什么"这个动作在两端都没有一个好地方：

- **Mac**：关掉最后一个窗口后一个窗口都没有，只剩 Dock 图标；启动时若无可恢复的会话，会凭空建一个你没起过名字的 `bento`。
- **iOS**：顶层名词是**主机**，必须 `主机列表 → 该主机的会话列表 → 终端` 三屏，并且进入中间那屏会**单独开一条 SSH 只为跑一次 `tmux ls`**。

两边都缺同一个东西，而且缺的是同一个东西。

## 2. 核心主张

**一个 provider（`OpenTargets.swift`），三种渲染，词汇与成员资格一致，只有权重和形态不同。**

| 场景 | 形态 | 根内容 |
|---|---|---|
| 任何窗口按 ⌘P / 点工具栏搜索框 | 浮层 | 全部：会话、最近、主机、命令 |
| 窗口存在但还没有会话 | **页面本身** | 品牌 + 三个"新建"动词 + SSH 菜单 + 会话/最近 |
| 右键 Dock 图标 | `NSMenu`，一眼扫，无搜索 | 同上，带条数上限 |

**2026-07-31 修订：页面不是"没有蒙层的命令面板"。**此前这一节写的是"空状态就是命令面板的第 0 层"，工具栏的搜索位因此被换成一个筛选**本页这十几行**的输入框。那是把两件事混成了一件：

- **搜索是全局的、在每个窗口里意思相同的东西**。会话窗口里它是 ⌘P 命令面板；启动器里它此前变成了一个只能找到本页那十几行的弱化版搜索——而面板自己的第 0 层内容来自**同一个 provider**，能找到的严格更多（每个会话、每条最近、每台主机）。用一个更弱的搜索盖住一个更强的，只因为它们长在同一个位置上。
- **页面是静态的**。它是一张短列表：你能造什么，你能回到哪儿。它不需要自己的查询、自己的模糊排序、自己的选中光标。

所以现在：**启动器窗口的工具栏搜索框和会话窗口的完全一样**，点它或按 ⌘P 都打开命令面板（`LauncherWindowController.presentPalette`）。没有 pane host 可挂 File / Pane 分区，就只给出空窗口下仍然成立的那几组——会话、最近、主机、三个动词——面板本身、位置、锚点都不变。

**主机因此仍然可搜。**页面上主机被折进左栏一个 `SSH ▸` 菜单（§6），菜单是搜不了的；但"打主机名 + 回车"这条路并没有消失，它在面板里，和它在会话窗口里的位置一模一样。搜索该在的地方只有一个。

两个根的内容量差异不是随意划的：**空窗口里没有东西可以施加命令**——分屏、查找、布局在那儿全无意义。有上下文才有命令。

## 3. 步骤栈

采用 VS Code quick pick 的链式模型：面板不关闭，列表整体替换，占位符显示上下文面包屑，**Esc 退一层而不是退出**。

```
level 0   空状态（页面）/ ⌘P（浮层）
            会话      bento          2 windows · 5 分钟前
            最近      claude         ~/code/bento-term
            主机      dev  [ssh] [tmux ▸]

level 1   dev › 选择会话…                    ← 每次都是实时枚举
            ↻ 正在连接 dev…        Esc 取消
            ─────────────────────────────
            build              2 windows
            scratch            1 window
            ＋ 新建会话…
            ＋ 新建 agent 会话…
            ▸ 不用 tmux，直接开 shell

level 2   dev › 会话名…                      ← 只问名字，回车即走
```

这个栈属于**面板**。启动器页面不在栈里（§2 修订）：它是静态的一张页，主机在它上面是左栏一个开菜单的行，不是一个可以往下推的层级。`tmux ▸` 的实时枚举因此只需要在面板里实现一次。

## 4. 为什么多轮交互要由面板承载

这不只是形式偏好，它解决一个结构性缺陷。

今天的流程是：点一下 → **立刻创建窗口** → 然后那个窗口得负责表达失败。这正是 2026-07-31 那个"点开远端 tmux 就卡死"的成因：一个已经存在的终端窗口，没有任何合适的方式说"其实我什么都没连上"，于是它就那么坐着。（三个并发原因见 commit `3480946`；另外 macOS 上 `showError` **从来没有被绑定过**，错误一直抛进虚空。）

改成面板承载之后：**主机解析、会话枚举、失败反馈全部发生在创建窗口之前；窗口只在你选中一个真实会话之后才诞生。**

失败于是有了天然的显示位置和天然的退出方式（Esc），而不需要给终端窗口发明一套错误 UI：

```
level 1   dev › 选择会话…
            ⚠ dev 上没有 tmux
              /bin/sh: 1: tmux: not found
            ▸ 不用 tmux，直接开 shell
```

## 5. 布局与权重

**2026-07-31 第二次修订：居中的两栏内容块。**上一版（动词在前、单栏、左上角起排）解决的是顺序问题，没解决**尺寸**问题：Bento 窗口是终端窗口，人们把它拖得很大，而这一页只有十几行短内容。结果是一大片空屏的左上角挂着一小截列表——读起来不像"这页就这么大"，像"列表没加载完"。

```
┌───────────────────────────────────────────────────────────────────┐
│ ◍ No Session │Parallel│Focus│ ⌕ Search commands… │+ New ⌄│⚙│▤│      │ ← 真工具栏，搜索位＝命令面板
├───────────────────────────────────────────────────────────────────┤
│                                                                   │
│            ▣▣                        Sessions                     │
│            ▣▣                          bento      2 windows · 5m  │
│                                        session-2  1 window · 1d   │
│         BentoTerm                                                 │
│                                      Recent Launches              │
│    New Terminal without tmux  ⏎        claude       ~/code/bento…  │
│      A quick local shell. Closing      npm run dev  ~/code/pers…   │
│      it discards it for good.          shell        ~/code/bent…   │
│    New Agent Session…                    2 more ⌄                 │
│      A fresh tmux session running                                 │
│      Claude, Codex or another…                                    │
│    New Empty Session                                              │
│      A blank tmux session on the                                  │
│      host. It keeps running after…                                │
│    SSH                             ▸                              │
│      6 hosts in ~/.ssh/config                                     │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
   └────────── 左栏：能造什么 ──────────┘ └──── 右栏：能回到哪儿 ────┘
```

**为什么是两栏而不是一栏拉长。**这十几行其实是两个不同的问题——"给我造一个"和"带我回到某个"——竖着叠起来，第二个看上去像第一个的延续。并排放，它们才明显是二选一，而且内容块得到一个**形状**，不是屏幕正中一条又高又窄的带子。

顺序不变，四个渲染面（`+` 菜单 / Shell 菜单 / 启动器 / Dock 菜单）仍然必须一致：

1. **New Terminal without tmux** —— 一次性 shell，单独一组、排第一，并且是本页的 ⏎（见下）。
2. **New Agent Session… / New Empty Session** —— 两条 tmux 创建路径，成对出现。
3. **SSH ▸** —— 一行，开的是工具栏那个菜单（§6）。
4. **Sessions** —— 正在跑的。
5. **Recent Launches** —— 先给三条，"N more" 展开。

**列表内部的权重不变，仍然不平均分配。**

- **会话 / 最近 = "继续"**：高意图、数量少，你多半就是想回到其中一个 → 整行。
- **主机 = "去个新地方"**：`~/.ssh/config` 里可能有几十条，单条意图密度很低 → **压成一行菜单**。此前是一行 chip + "10 ▸" 展开器；chip 行的问题是它同时是页面上最宽的东西，栏一窄就第一个崩，而一个菜单在任何宽度下都只占一行、说的还是同一件事。
- **最近仍然折叠**：第四新的那条本来就很少被点 → 先给三条。

### 内容块的尺寸：上限、断点、以及窗口小到极限时

居中就必须有天花板，否则 2500pt 宽的窗口会把两栏拉到相隔一米，读起来是两份互不相干的列表而不是一个块。数字定在 `LauncherLayout`：

| 量 | 值 | 理由 |
|---|---|---|
| 左栏 | 固定 **360pt** | 内容是固定的：三条带整句解释的动作行 + 一行 SSH。360 刚好够那三句话折成两行而不在句子中间截断 |
| 间距 | 40pt | |
| 右栏 | **300–400pt** 弹性 | 内容是会话名和 `~/` 缩写路径；短了难看，超过 400 不再有收益 |
| 块宽 | 700–**800pt** | 上面三项之和 |
| 外边距 | 32pt | |
| **折叠断点** | 窗口内容宽 **764pt** | = 700 + 2×32。低于它右栏就要开始截断会话名了 |
| 单栏块宽 | ≤ 420pt | |

- **折叠成什么**：右栏整体落到左栏**下面**，分区顺序完全不变（Sessions → Recent Launches）。没有任何东西被重排或藏起来，只是重新换行——所以"宽版"和"窄版"不是两种设计，是同一个顺序的两种折法。
- **再窄**：单栏块跟着窗口缩，直到终端窗口自己的 480pt 下限；那时块宽 416pt，仍然完整。**任何宽度都不裁剪。**
- **竖向**：块在装得下时垂直居中，装不下时容器接管滚动（`ScrollView`）。窗口被拖成一条横带也只是滚动，不会切掉内容。
- **右栏为空时不画右栏**：一台有 ssh config 但什么都没跑的机器，右半边空着会像"这一半没加载出来"。这种页面直接走单栏形态（`hasRightColumn`）。

### 词汇：一个概念一个名字

### 词汇：一个概念一个名字

三处旧叫法互相打架：工具栏 `+` 叫 `New Session with Agent…`，启动器页脚叫 `New Agent Session…`；Shell 菜单把空 tmux 会话叫 `New Session`，工具栏叫 `New Empty Session`；同一个无 tmux 终端在 Shell 菜单里叫 `New Window (no tmux)`。定稿：

| 概念 | 名字 | 为什么是它 |
|---|---|---|
| 一次性本地 shell | **New Terminal without tmux** | 唯一同时说清"是什么"和"缺什么"的写法；`New Window (no tmux)` 说的是窗口，可它其实是个关掉就没的终端 |
| agent 会话 | **New Agent Session…** | 与下一行构成同构（`New _ Session`），两行只差一个词；`New Session with Agent…` 破坏了这个对仗。省略号保留——它开的是向导 |
| 空 tmux 会话 | **New Empty Session** | 旁边一旦坐着 agent 会话，光说 `New Session` 就不再唯一 |

字面与解释句都收在 `LaunchAction`（`OpenTargets.swift`）里，四个面渲染同一份数据——这正是 provider 存在的前提：面之间不许各说各的。

### 这一页不筛选（推翻上一版）

上一版这里写的是"动作行钉住不参与筛选，⏎ 跟着搜索结果走，打开即可打字"。整套没了，因为它的前提（工具栏搜索位＝本页筛选框）在 §2 里被推翻了。现在：

- **页面是静态的**。没有查询、没有模糊排序、没有选中光标、没有 ↑↓ 列表导航。它是一张短列表加两栏排版。
- **搜索在面板里**，工具栏那个位在启动器和会话窗口里是同一个东西。主机、会话、最近全都在那儿可搜，而且比旧的本页筛选找得更多。
- **⏎ 仍然是 New Terminal without tmux**。没有光标要跟随，所以这条用的是 SwiftUI 的 default action（那一行右侧画一个 `⏎`，键不当暗号用），不是重新长回来的列表选中模型。`⌘N ⏎ = 一次性 shell` 这条肌肉记忆因此保住，代价只有一个修饰符，没有导航状态。
- **没有 ↑↓**：两栏之间没有横向键，因为 ←/→ 属于面板搜索框里的光标；为了在两栏间移动而抢走编辑查询用的键，是在给一个不存在的问题制造真问题。

**没东西可开时**（没会话、没历史、没有 ssh config）：页面不是另一块空屏。三条动作本来就无条件存在，所以只在它们下面加一句话——"Nothing running to open — no tmux sessions, no recent launches, no hosts in ~/.ssh/config"——把找过哪三处说出来，读起来才是"确实没有"而不是"没加载出来"。这种页面同时也是单栏形态（右栏无内容可画）。

### 它不是另一种窗口：同一个窗口，只是还空着

**2026-07-31 再修订。**"启动器该多大"这个问题此前来回过一次（初版继承会话窗口 frame；中途改成固定 660 × 520 居中，因为 ⌘N 从近乎全屏的终端上按出来会得到 2544pt 宽、只装九行的空页；再改回继承）。**这个问题现在不存在了**，因为它建立在一个错误前提上：把启动器当成一种自己的窗口，于是要为它选一个尺寸。

真相是：**启动器就是终端窗口，只是里面还什么都没有。**同一个 `NSWindow` 类、同一个 `TerminalSessionWindow.makeShell()`、同一套 style mask 与 `fullSizeContentView`、同一个 `tabbingIdentifier`、同一个工具栏、同一份 `BentoWindowFrame` 记忆。差的只有**内容**，以及工具栏上那几个此刻无所指的控件。

以前它是"另一种窗口"，症状有三个而病只有一个：

1. **几何不传播** —— 它 `setFrameUsingName` 读、却从不 `setFrameAutosaveName` 写，你把它调好的尺寸被扔掉。现在它和会话窗口抢同一个名字，`BentoWindowFrame` 负责"同一时刻只有一个持有者"；**填充是原地的，所以持有权跟着同一个 NSWindow 走，中间没有空档**。
2. **⌘N 不认标签页偏好** —— `4f93e6b` 让 ⌘N 强制独立窗口，理由是"`newSessionPlacement` 回答的是新**会话**落在哪，按 ⌘N 的人已经回答过了"。那条理由随着 ⌘N 不再直接建会话而作废：⌘N 现在产出的是一个**即将成为会话**的空窗口，偏好当然适用。现在它和会话窗口走同一条路（`shouldOpenAsTab` 就加入标签组）。
3. **看起来像另一个 App** —— 它根本没有工具栏。现在有，而且是同一个。

**工具栏上少了什么。**只有那些真的无所指的：会话名按钮（`No Session`）和 Parallel│Focus **禁用而不隐藏**——隐藏会改变工具栏宽度，于是"回答问题"这个动作会让剩下的控件横向跳一下，正是原地填充要消灭的那种"冒出个新窗口"的印象；tmux 窗口段是唯一被拿掉的，因为空列表不是"禁用的控件"而是"没有东西"，而它那个位置本来就和搜索共用（单窗口会话显示的也是搜索）。New ⌄ 菜单里的 tmux window / pane 两组也去掉——菜单是打开、读完、关掉的东西，宽度不是谁在依赖的几何。

**搜索位里坐的就是会话窗口那个按钮。**这一条来回过两次。最初页面顶部有自己的搜索框（于是工具栏那个下面十几点的地方还有第二个搜索框，很糟）；接着页面那个被折进工具栏的搜索位，代价是一个工具栏控件要持有 first responder 并把方向键交给它不拥有的列表。**现在两个都不要**：那个位是打开命令面板的按钮，和会话窗口里一模一样，两种窗口在这一点上的差别归零。理由见 §2——把一个只能找到本页十几行的弱搜索，盖在一个能找到全部的强搜索上面，是这个位置唯一不该发生的事。

**窗口标题**是 `BentoTerm · New Window`。会话窗口叫 `BentoTerm · <会话名>`，这个还没有内容，所以它说出**产生它的那个动作**。标题栏本身是隐藏的，但这串字在两个地方是有用的：Window 菜单，以及——现在启动器能当标签页了——标签上的字，那里光写 `BentoTerm` 会和旁边的默认会话分不清。

**尺寸**因此不再是启动器自己的事：它开在所有 Bento 窗口共享的那份几何上，并且**会把你改后的尺寸记回去**。大屏上的空页仍然是两害里轻的那个，理由不变：一个在你做选择时改变尺寸的窗口读起来就是"弹出了一个新窗口"，而那次尺寸变化和 ghostty surface 创建落在同一个 runloop turn 里，没有稳定的"之前"可供动画。

（一个相关的坑：给 `NSWindow` 赋 `contentViewController` 会把窗口**缩到那个控制器的 fitting size**——实测这个 split view 是 500 × 500。新窗口看不出来，因为下一行就设真尺寸；**被接管的启动器窗口则是当着用户的面缩一下**。所以 `TerminalWindowManager` 在接管时先存下 frame、换完内容再放回去。）

### 放什么、不放什么（2026-07-31 明确翻转其中一条）

**放**：一个大 logo + 字标 **BentoTerm**，在左栏最上面。

这一条**直接推翻**了本节此前那句"不放：hero 图、标语、架构图"。是知情推翻，不是漏看，所以把两者的区别记下来，免得下次有人拿旧句子来撤掉它：

- **那条禁令针对的是"页面会长胖"**。写它的时候，失败模式是这一页不由自主往里塞标语、架构图、"三步开始使用"——也就是刚删掉的 onboarding 顺着空白长回来。这个风险依然真实，**禁令的其余部分一字不改**。
- **logo 解决的是相反的问题**：这一页内容太少、屏幕太大。它不是宣传物，它是**锚**——把居中的内容块钉住，并且在一个什么都没有的窗口里回答"我现在看的是哪个 App"。一个空白的终端窗口没有别的东西能回答这个。

**仍然不放**：标语（一句夸自己的话，纯宣传，和"你能打开什么"无关）、架构图、"三步开始使用"、任何形式的引导序列。判据没变：**这一页的职责只有一句——这些是你可以打开或新建的东西。**logo 通过了这个判据（它不说话，它定位），标语通不过。

**logo 来源只有一处**：`LauncherBrand`（`LauncherWindow_macOS.swift`）。今天它取 bundle 里的 app icon（`BentoTermMac/Resources/Assets.xcassets/AppIcon.appiconset`，由 `docs/bento-icon.svg` 生成）。新图标正在单独设计，换过来是改这一行，不用翻视图代码。字标固定写 **BentoTerm**，和 App 名、窗口标题、Homebrew formula 一致。

## 6. 主机：一行，开工具栏那个菜单

页面左栏：

```
SSH                                              ▸
  6 hosts in ~/.ssh/config
```

点它弹出的是 `SSHHostMenu`——**和工具栏 `New ⌄` 里那两行同一份对象**，不是同样的措辞维护两遍：

```
New SSH Connection      ▸   dev / orb / home / …
New Remote tmux Session ▸   dev / orb / home / …
```

**为什么不发明第三套词汇。**`LaunchAction` 已经为三个创建动词做了这件事（§5"一个概念一个名字"）；主机列表是它没覆盖到的那一份，现在补上：标题、tooltip、顺序、"没有主机"的提示，都是同一个 `SSHHostMenu` 出的。启动器那一行因此只是**去同一个菜单的捷径**，不存在"哪一个才算数"的问题。

- **New SSH Connection** —— 普通 ssh 终端，**零网络等待**，不枚举。
- **New Remote tmux Session** —— 远端 tmux 会话，平铺 panes。两者的区别是**什么东西能活下来**：普通连接随 tab 死掉，会话不会。

主机每次开菜单都重读 `~/.ssh/config`（改了文件不用重启），而且只读这一个本地小文件——"不许阻塞在网络上"在这里同样成立。

§3 那个 `tmux ▸` 实时枚举的 level 1 仍未实现；实现之后它属于**面板**，不属于这一行（§3 修订）。

## 7. 新建会话的两条路径，形态不同

对应现有的两种创建方式，且**刻意不做成同一种形态**：

- **普通会话** —— 留在面板里，一个输入框，回车即走。它就该只有一道题。
- **agent 会话** —— 从面板**跳出**到现有的向导表单，不链式化。

理由：布局选择是**二维的**（`TmuxLayout` 的九宫格 / 主从 / 三列，带 SF 图标），线性 quick pick 渲染不了；硬拆成四步问答（名字→目录→agent→布局）比一张表单更烦。VS Code 同样如此——有些命令开的是编辑器而不是继续链式。

**面板负责路由，不负责承载一切。**

## 8. 不缓存枚举结果

已决定：`tmux ▸` 每次都实时枚举。三个后果：

1. **异步层的取消与进度不是可选项。** 每次都是真实往返（`dev` 实测约 300ms，链路差时数秒）。必须有进行中指示，**Esc 必须真的杀掉那条 ssh**。
2. **不许预取。** 不能因为"反正要连"就在悬停时预热——那会在你只是划过列表时对每台主机发起 ssh。只在显式动作时连接。
3. **iOS 根屏的"会话"分区被掏空** —— 见 §10 待决。

## 9. Mac 的空状态何时出现

三条，按 `openMainWindow` 的实际分支写（本节此前把 Dock 那条说宽了）：

- **启动时**：`mac_last_terminal_sessions` 为空（或里面的会话在服务器上都不在了）→ 启动器。有可恢复的就直接恢复，不问。
- **Dock 图标唤起时**：`ccbeb3a` 之后**不只是**"无可恢复的会话"这一种情况。本次运行内如果用户**自己把窗口一个个关光了**，`closedEverythingByHand` 会置位，之后点 Dock 图标一律出启动器，即便恢复列表非空——手动清空屏幕是一个决定（"我收拾完了，给我看看有什么"），和 ⌘Q 之后回来（"我做到一半"）不是同一件事。该标记在任何会话窗口重新存在时立刻清掉，⌘Q 走 `isTerminating` 不置位，所以下次冷启动照样恢复。
- **⌘N**（见下）

**关掉最后一个窗口仍然是没有窗口**（既有决定不变）。空状态是"窗口存在但还没内容"，不是"没有窗口"。

### ⌘N 的语义修正

`4f93e6b` 之前是"⌘N 立刻新建窗口 + 一个自动命名的新会话"。有了空状态之后改为：

- **⌘N** = 开一个新窗口，**然后问你要放什么**（空状态）
- **⌘⇧T** = 别问，直接给我一个 **New Empty Session**
- **⌥⇧⌘T** = 别问，直接给我一个 **New Terminal without tmux**

三种意图本来就存在，给它们各一个键，都诚实。旧行为的问题是 ⌘N 会创建一个叫 `session-3` 的东西——一个你没起过的名字。

而且 §5 改序之后，⌘N 也不再只是"问你"：**⌘N ⏎ = 一次性 shell**，比 ⌥⇧⌘T 更好按，也正好是最高频的那个意图。（页面已经没有选中光标了，这条现在由那一行的 default action 承担，见 §5"这一页不筛选"。）

**⌘N 不再强制独立窗口。**`4f93e6b` 让它绕过 `newSessionPlacement`，理由是那个偏好回答的是"新**会话**落在哪"，而按 ⌘N 的人已经回答过了。那条理由在 ⌘N 直接建会话的时代成立，现在不成立了：⌘N 给出的是一个还没决定内容、**马上就要变成会话**的窗口，所以它必须和会话走同一条路径——`shouldOpenAsTab` 为真就 `addTabbedWindow` 进最前那个窗口的标签组，否则独立。否则用惯标签页的人每按一次 ⌘N 就多一个游离窗口，然后他选的东西落在那个窗口里，而不是他放其它所有东西的那条标签栏上。

**一个仍然存在的、和启动器无关的缺口**：`newSessionPlacement = .window` 时代码给的是 `tabbingMode = .automatic`，而 AppKit 的 automatic 会跟随**系统**的"打开文稿时优先使用标签页"。系统设为「总是」时，选了「In a New Window」的用户拿到的仍然是标签页——会话窗口和启动器窗口一样如此（实测：两个会话窗口在 `.window` 偏好下也合成一组）。改成 `.disallowed` 能让这个偏好真的生效，但会连带取消 Merge All Windows 和把标签拖出来，而"偏好只决定默认、不决定可能"是既有的明确决定。留待单独判断。

## 10. iOS / iPadOS 对齐

**同样的分区、同样顺序、同样词汇。区别只在生命周期**：Mac 上它是**空状态**（偶尔出现），iOS 上它就是**根**（永远是第一屏）。

（Mac 的两栏与"主机折进菜单"是桌面尺寸下的取舍，不自动适用于 iOS：iPhone 上没有第二栏可放，而 iOS 也没有 `~/.ssh/config`。iOS 落地时重新判断，别照抄栏数。）

这同时替掉了 iOS 的"每台主机一屏会话列表"这个中间层，那两次 SSH（其中一次只为跑 `tmux ls`）也收敛成面板里的一次枚举。

iPhone 上面板是 sheet / push，iPad 上是同一个面板；iPad 的根应改为 `NavigationSplitView`（侧边栏 = 这份列表，detail = 终端），对应 Mac 的"会话 = 窗口标签，tmux 窗口 = 侧边栏"。

**⚠ 待决**：§8 的不缓存决定会让 iOS 根屏的"会话"分区只剩当前已连接的那些，其余会话必须先选主机再等一次往返才可见——**iOS 的顶层名词会因此被迫退回"主机"**，也就是本文一开始要解决的问题。Mac 没这个问题，因为本地 `tmux ls` 是瞬时的。

倾向：**iOS 破例缓存**。失效风险很低——显示一个已被别处杀掉的会话，点下去是 `new-session -A`，会重建同名的，不报错。

## 11. 词汇

统一到 Mac 的 `服务器 / 会话 / 窗口 / pane`，连接动作只用一个动词。

iOS 现状有五个动词（Connect / Attach / Start / Create / Open / Launch），一屏之内就能看全；且 `Host` 与 `Server` 的用法与 Mac 相反（iOS 管机器叫 Host，却把 hostname/port 那节叫 Server）。

另有一处假话待清：`WelcomeFlowView` 写着 "Reads your ~/.ssh/config" —— iOS 上没有任何 ssh config 读取，那是 Mac 刚获得的能力。

**未决**：`Focus / Parallel` 是 iOS 独有的、盖在 tmux 窗口之上的一层说法，Mac 的模型里没有这个名词。要么 Mac 采纳，要么 iOS 放弃，不能两端各说各的。这是产品身份问题。

## 12. 不在本设计范围内的后续工作

- **交互式认证 UI**。需要密码 / 2FA / 未验证 host key 的主机**目前完全不可用**：界面渲染的是 tmux 面板，而 tmux 根本没启动，没有地方输入。现在会在 12 秒后失败并引用真实提示文本，不再永久卡死。但"任何 sshd + tmux"这个前提要求它必须被解决。
- **远端 agent 会话**。目录选择现在用 `NSOpenPanel`（本地文件系统），远端需要走 ssh 的目录浏览器；agent 探测现在是本地 `command -v` 且只返回第一个装了的，远端需要一次往返探测全部。这块与"最近"分区里的远端目录是同一批基础设施。
- **App Intents / Spotlight**。同一个 provider 的第四个出口。
